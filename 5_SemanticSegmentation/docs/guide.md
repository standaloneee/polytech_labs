## Введение

Семантическая сегментация — задача компьютерного зрения, в которой каждому пикселю изображения присваивается метка класса. В данной работе решается задача **бинарной сегментации** кровеносных сосудов на изображениях сетчатки глаза.

Автоматическая сегментация сосудов сетчатки имеет важное медицинское значение:
- Диагностика диабетической ретинопатии
- Оценка сердечно-сосудистых заболеваний
- Мониторинг глаукомы
- Скрининг недоношенных новорождённых

## Теоретические основы

### Семантическая сегментация vs другие задачи

| Задача | Выход | Пример |
|--------|-------|--------|
| Классификация | Одна метка на изображение | «Есть патология» |
| Детекция | Bounding boxes | Область аномалии |
| **Семантическая сегментация** | **Маска (метка каждого пикселя)** | **Карта сосудов** |
| Instance segmentation | Отдельные маски для каждого объекта | Каждый сосуд отдельно |

### Encoder-Decoder архитектура

Классический подход к сегментации использует encoder-decoder структуру:

1. **Encoder** (сжатие): извлекает признаки, уменьшая пространственное разрешение
2. **Decoder** (восстановление): восстанавливает пространственное разрешение
3. **Skip connections**: передают детали от encoder к decoder для сохранения мелких структур

## Датасет DRIVE

### Описание

**DRIVE** (Digital Retinal Images for Vessel Extraction) — стандартный бенчмарк для сегментации сосудов сетчатки.

- **Источник:** 40 цветных фотографий сетчатки
- **Камера:** Canon CR5, 45° поле зрения
- **Разрешение:** 565×584 пикселей
- **Формат:** .tif (изображения), .gif (маски)
- **Разметка:** Ручная сегментация двумя экспертами-офтальмологами

### Разделение данных

| Множество | Количество | Источник |
|-----------|-----------|----------|
| Train | 16 | Первые 16 из training set |
| Validation | 4 | Последние 4 из training set |
| Test | 20 | Полный test set |

### Характеристики

- **Дисбаланс классов:** сосуды занимают ~12% пикселей, фон ~88%
- Это типичная проблема для медицинской сегментации, которая мотивирует использование Dice Loss

## Архитектура U-Net

### Базовый U-Net

U-Net был предложен в 2015 году специально для медицинской сегментации (Ronneberger et al.).

```
Вход (3, 512, 512)
   │
   ├── Encoder Block 1: Conv(3→64) → Conv(64→64) → MaxPool
   │   ├── (64, 512, 512) → skip connection ─────────────────┐
   │   └── (64, 256, 256) ↓                                  │
   │                                                          │
   ├── Encoder Block 2: Conv(64→128) → Conv(128→128) → MaxPool
   │   ├── (128, 256, 256) → skip connection ───────────┐    │
   │   └── (128, 128, 128) ↓                            │    │
   │                                                     │    │
   ├── Encoder Block 3: Conv(128→256) → Conv(256→256) → MaxPool
   │   ├── (256, 128, 128) → skip connection ──────┐    │    │
   │   └── (256, 64, 64) ↓                         │    │    │
   │                                                │    │    │
   ├── Encoder Block 4: Conv(256→512) → Conv(512→512) → MaxPool
   │   ├── (512, 64, 64) → skip connection ───┐    │    │    │
   │   └── (512, 32, 32) ↓                    │    │    │    │
   │                                           │    │    │    │
   ├── Bottleneck: Conv(512→1024) → Conv(1024→1024)│    │    │
   │   └── (1024, 32, 32) ↓                   │    │    │    │
   │                                           │    │    │    │
   ├── Decoder Block 4: Up(1024→512) + cat ────┘    │    │    │
   │   └── Conv(1024→512) → Conv(512→512)           │    │    │
   │       (512, 64, 64) ↓                          │    │    │
   │                                                │    │    │
   ├── Decoder Block 3: Up(512→256) + cat ──────────┘    │    │
   │   └── Conv(512→256) → Conv(256→256)                 │    │
   │       (256, 128, 128) ↓                             │    │
   │                                                     │    │
   ├── Decoder Block 2: Up(256→128) + cat ───────────────┘    │
   │   └── Conv(256→128) → Conv(128→128)                      │
   │       (128, 256, 256) ↓                                  │
   │                                                          │
   └── Decoder Block 1: Up(128→64) + cat ─────────────────────┘
       └── Conv(128→64) → Conv(64→64)
           (64, 512, 512) → Conv1x1(64→1) → Выход (1, 512, 512)
```

**Количество параметров:** ~7.8M

### U-Net + ResNet34

Замена encoder на предобученный ResNet34:

- **Encoder:** ResNet34 (предобучен на ImageNet, ~21M параметров)
  - conv1 + bn1 + relu: 3 → 64 (stride 2)
  - maxpool: stride 2
  - layer1: 64 → 64
  - layer2: 64 → 128
  - layer3: 128 → 256
  - layer4: 256 → 512

- **Decoder:** 5 уровней с skip connections

**Преимущества:**
- Предобученные веса ускоряют обучение
- Более мощные признаки из ImageNet
- Лучшая генерализация при малом количестве данных

**Количество параметров:** ~24M

## Loss-функции

### Binary Cross-Entropy (BCE)

```
BCE = -1/N Σ [y·log(ŷ) + (1-y)·log(1-ŷ)]
```

- Стандартная loss для бинарной классификации
- Считает каждый пиксель независимо
- **Проблема:** при дисбалансе классов (88% фон) модель может предсказывать «всё — фон» и получать низкий loss

### Dice Loss

```
Dice = 2·|A∩B| / (|A| + |B|)
DiceLoss = 1 - Dice
```

- Напрямую оптимизирует метрику Dice coefficient
- Не зависит от дисбаланса классов (учитывает только область overlap)
- Smooth factor (ε=1) для числовой стабильности

### Combined Loss (BCE + Dice)

```
CombinedLoss = 0.5·BCE + 0.5·Dice
```

- Сочетает стабильность градиентов BCE с инвариантностью к дисбалансу Dice
- Часто даёт лучшие результаты, чем каждая по отдельности

## Метрики качества

### Dice Coefficient (F1 Score)

```
Dice = 2·TP / (2·TP + FP + FN)
```

- Основная метрика для медицинской сегментации
- Диапазон: [0, 1], чем выше — тем лучше
- Эквивалентен F1-score

### IoU (Intersection over Union, Jaccard Index)

```
IoU = TP / (TP + FP + FN)
```

- Стандартная метрика для сегментации в компьютерном зрении
- Более строгая, чем Dice: IoU ≤ Dice всегда

### Pixel Accuracy

```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
```

- Доля правильно классифицированных пикселей
- **Внимание:** может быть обманчиво высокой при дисбалансе классов

### Sensitivity (Recall)

```
Sensitivity = TP / (TP + FN)
```

- Способность обнаруживать сосуды (True Positive Rate)
- Важна для медицинской диагностики

### Specificity

```
Specificity = TN / (TN + FP)
```

- Правильное определение фона (True Negative Rate)
- Дополнение к Sensitivity

## Аугментации данных

Аугментации особенно важны при малом количестве данных (20 обучающих изображений).

| Аугментация | Параметры | Обоснование |
|-------------|-----------|-------------|
| Горизонтальное отражение | p=0.5 | Сетчатка может быть зеркальной |
| Вертикальное отражение | p=0.5 | Изображение может быть перевёрнуто |
| Поворот на 90°/180°/270° | равновероятно | Ориентация камеры |
| Яркость | ±20%, p=0.3 | Вариации освещения |
| Контрастность | ±20%, p=0.3 | Различие в камерах |
| Гауссов шум | σ=0.02, p=0.2 | Шум сенсора |

**Важно:** аугментации применяются одинаково к изображению и маске (геометрические), но только к изображению (фотометрические).

## Процесс обучения

### Гиперпараметры

- **Optimizer:** Adam (β₁=0.9, β₂=0.999)
- **Learning rate:** 1e-4
- **Scheduler:** ReduceLROnPlateau (mode='max', factor=0.5, patience=5)
- **Early stopping:** patience=10 эпох без улучшения val Dice
- **Batch size:** 4
- **Image size:** 512×512

### Пайплайн

1. Загрузка изображения (.tif) и маски (.gif)
2. Resize до 512×512
3. [Аугментации] (если включены)
4. Нормализация изображения в [0, 1]
5. Бинаризация маски {0, 1}
6. Forward pass → logits (без sigmoid)
7. Loss (BCE / Dice / Combined)
8. Backward pass → обновление весов
9. Валидация каждую эпоху

### Выход модели

Модель выдаёт **logits** (без sigmoid):
- BCEWithLogitsLoss и DiceLoss внутри применяют sigmoid
- При инференсе: `pred = sigmoid(logits) > 0.5`

### Кросс-платформенность

Проект автоматически определяет доступное устройство:
1. **CUDA** (NVIDIA GPU) — рекомендуется
2. **MPS** (Apple Silicon) — поддерживается
3. **CPU** — работает, но медленнее

### Воспроизводимость

- Фиксированные seed'ы не устанавливаются глобально (из-за аугментаций)
- Результаты могут незначительно отличаться между запусками
- Все гиперпараметры сохраняются в checkpoint и JSON
